Built the same way

So you can add one without wondering what it does to your machine, your settings or your bill.

No dependencies

Node 18 or newer and nothing from npm. There is nothing to audit but the code itself.

Token cost is a feature

Hooks talk to you, not to the model. Skills Claude does not need are user-only. Every README states what each part costs.

Your settings stay yours

A backup before every write, only their own keys, invalid JSON left alone, and an uninstall that restores what you had.

Honest READMEs

Each says what was verified and how, and what was not. Each runs its tests on Windows, macOS and Linux with Node 20, 22 and 24.

Tested together

One end-to-end run does what a new user would, on a clean machine, and CI repeats it every week so a Claude Code update that breaks a tool shows up.

  1. A throwaway home and Claude Code config that already hold settings of their own.
  2. Every tool installed from GitHub, and every hook run exactly as settings.json lists it, with the JSON Claude Code sends: guardrails denies rm -rf /, notify pings after a long turn, cost guard holds a prompt over a hard budget, two teammates share a session through one git remote, a replay escapes hostile text.
  3. The one-command setup run as a user would, in a second home folder: install with options, the setup page started for real and driven through its own API, Done, and everything uninstalled again.
  4. All seven plugins installed from this marketplace with claude plugin install, their own hooks run from the installed copies, their token estimate checked, and the HUD's engine tests run inside Claude Code.
  5. Everything uninstalled, and settings.json checked to be exactly what the user had.
